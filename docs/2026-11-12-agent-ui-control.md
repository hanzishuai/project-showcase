# 2026-11-12 实验：能操控系统的数字人 Agent

分支：`feat/agent-ui-control`（实验性，不影响 main）

## 结论

**能做到。** 数字人现在可以听懂「打开/切到/筛选/看看某个项目」这类话，自己操作界面：
切页面、切看板视图、设筛选、开详情抽屉、开图片灯箱、切后台页签。
一句话链路：**LLM function calling → SSE action 事件 → 前端动作总线 → 页面处理函数**。

实测 4 个指令全部生效（见下方「验收」）。

## 架构

```
用户说话
  ↓
<RagAvatar>（数字人组件，stream-mode=sse）
  ↓ 自定义 fetch（src/agent/fetch.ts）
POST /api/v1/agent/ask  ← 带上当前界面状态 ui
  ↓
后端 app/agent.py
  ├─ 检索参考资料（事实类问题用）
  ├─ 调 DeepSeek（tools + tool_choice=auto）
  └─ SSE：meta → action…（白名单动作）→ token…（话术）→ done
  ↓
fetch 把响应流 tee 成两路
  ├─ 一路原样给组件做流式显示（SDK 忽略未知的 action 事件）
  └─ 一路自己解析 → dispatchAction()
       ↓
   动作总线（src/agent/bus.ts）：按工具名找处理函数，找不到就排队重试 3 秒
       ↓
   App.vue（navigate_page / open_admin_tab）
   KanbanPage.vue（set_board_view / filter_board / open_project / close_drawer / open_gallery / close_gallery）
   AdminPage.vue（跟随 uiState.adminTab）
```

## 踩过的坑

1. **组件默认优先 WebSocket**（`streamMode: auto`），而自定义 fetch 只拦 HTTP —— 请求直接走 WS，
   包装完全失效（表现：数字人答「我不能切换页面」）。改成 `stream-mode="sse"` 后正常。
   > 如果以后要用回 WS 单连接流，需要在 WS 层也加 action 通道。
2. **工具语义要写清楚**：「打开后台知识库页面」最初只触发了 `navigate_page(admin)`，落在工作概览。
   把 `open_admin_tab` 描述成「已包含进入后台，不要叠加 navigate_page」后才稳定。
3. **模型偶发空返回**：单次调用大约 1/10 概率返回空 content，已加一次重试 + 兜底话术。

### 2. 动作失败有反馈

动作总线里对处理函数返回 `false`（或抛错）的情况做了兜底：用 Arco `Message` 弹一句人话
（如「没找到这个项目，看看名字对不对？」），不再静默失败。

### 3. 写操作：已按产品定位移除

**数字人只负责介绍和带路，不代劳写操作。** `rebuild_knowledge_index` 已从工具白名单删除，
前端对应处理函数与确认弹窗一并移除；系统提示词新增一条硬规则：

> 你只负责介绍和带路，不替用户执行任何写操作（保存、删除、上传文档、重建索引、修改数据）。
> 用户要求这类操作时，告诉他去哪个页面的哪个按钮自己做，不要调用动作、也不要假装已经做了。

实测：

| 用户说 | 结果 |
|---|---|
| 重建知识库索引 | 无动作；回答「这是写操作，我不能替你做。你到管理后台的知识库管理页，点「重建索引」按钮就行。」 |

## 2026-11-12 追加：动作依赖、语音动作断言、性能基准、LLM 主备

### 1. 动作间依赖：open_gallery 支持直接带项目

「打开学术讲座预约平台，再打开它的图片」之前只做前一半——因为模型没法保证「详情已打开」这个前置条件。
现在 `open_gallery(index?, project?)` 支持直接传项目名，前端会先切看板、打开该项目，再开灯箱：

> 「打开学术讲座预约平台，再打开它的图片」→ 一个动作 `open_gallery(project=学术讲座预约平台)` + 「这就打开…并把它项目里的图片调出来给你看。」

同时「那它的图片呢」这类追问现在也走这条路径，测试断言改为「打开详情」或「一步开详情+图片」都算对。

### 2. 语音 → 动作 断言

语音测试从「识别出文字」升级到验证**真的执行了界面操作**：说「打开管理后台」后断言 `location.hash === '#/admin'` 且后台挂载。
**7 / 7 通过。**

### 3. 性能基准脚本

新增 `scripts/agent-bench.mjs`（`node scripts/agent-bench.mjs 20`）：先发一次预热请求，再连跑 N 次，输出首字延迟/总耗时的 min·P50·P90·max，并按「动作/事实/复合」分类。

|---|---|---|---|---|
| 首字延迟 | 582ms | **900ms** | 1101ms | 1239ms |

### 4. 纯动作指令跳过检索

「打开管理后台」「看下一张」这类短指令不需要资料，新加启发式：短句、无疑问词、以动作动词开头 → 跳过向量检索。
动作类首字 P50 从 1324ms 降到 **778ms**。

### 5. LLM 主备双通道（今天真的用上了）

联调中发现 DeepSeek 账户余额耗尽（HTTP 402 Insufficient Balance），Agent 会直接报「助手暂时不可用」。

## 2026-11-12 追加：动作参数修复 + 多动作时序 + 基准阈值

### 1. 动作参数校验与自动修复

模型偶尔会给空参数（实测出现过 `open_project({})`、`open_admin_tab({})`）。新增 `_repair_actions`：

- **缺项目名**：从「问题 + 模型话术 + 看板上下文」里找项目名补上；找不到就丢弃并补一句「没听清你想打开哪个项目」；
- **缺枚举参数**：`open_admin_tab` 默认 dashboard、`set_board_view` 默认 board；
- **缺必填参数**：丢弃并记 `agent_action_missing_args` 日志，不再把坏动作发给前端。

实测「先回到看板，再打开**学期**学术讲座预约平台的详情」（用户打错字）→ 自动补全为「学术讲座预约平台」并执行，同时提示「看板上它的名字是学术讲座预约平台，没有『学期』两字」。

### 2. 「说到就要做到」一致性规则

模型有时嘴上说「这就打开」却没调动作。新增规则要求「说了就要调，不确定就别说已经做了」，并要求每次调动作都配一句话。实测 4 条多动作指令全部正确。

### 3. 多动作时序

一条指令里最多 4 个动作按 SSE 顺序执行，前端总线顺序派发，跨页场景（先 navigate 再操作）靠动作队列兜住挂载时机。新增 3 条多动作用例。

### 4. 基准阈值（性能回归报警）

`agent-bench.mjs` 支持阈值：默认首字 P90 ≤ 1800ms、总耗时 P90 ≤ 2200ms，超阈值退出码 1（可用 `--max-p90=2000` 覆盖）。

## 怎么扩展一个新动作（三步）

1. `backend/app/agent.py`：在 `SYSTEM_MAP` 加一句说明，`TOOLS` 加一个 function 定义；
2. 前端对应页面：`registerAction('工具名', handler)`；
3. 需要的话在 `uiState` 加字段，让模型知道上下文。

写操作建议走：模型先返回 `propose_action` → 前端弹确认 → 用户确认后再发一次执行请求。
